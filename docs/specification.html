Specification

The eight parts of the specification of Pupitre: the model, the access rules, the runner, the API, the configuration, the security and the delivery.

On this page
  1. The parts
  2. Key words
  3. Where to start

This page comes from docs/SPECIFICATION.md in the repository.

The specification of Pupitre has eight parts. Each part is a Markdown file in docs/. The specification and the code MUST agree. A difference is a defect. A fix changes the part or the code, and the paragraph numbers stay the same.

Each part uses ASD-STE100 Simplified Technical English. A numbered paragraph keeps its number in all later versions. The code and the tests cite the paragraph numbers.

The parts

PartFileContent
Part 1: Overview01-overview.mdPurpose, scope, architecture, crates, terms and fixed decisions
Part 2: Model and storage02-model-and-storage.mdIds, documents, the canonical form, schemas, layers, the Store contract, the two backends, secrets and the catalog
Part 3: Access03-access.mdThe modes open and authzen, the resource tree, the actions, the questions of each route, the action document and the options route
Part 4: Runner and commands04-runner-and-commands.mdRuns, the queue, the snapshot, the child process, events, the guard of an apply and commands
Part 5: API and page05-api.mdThe listeners, the routes, the bodies, the errors and the pages
Part 6: Configuration06-configuration.mdThe file, the blocks, the checks, the contradictions, the command line, the logs and the metrics
Part 7: Security and limits07-security-and-limits.mdThreats, controls, headers, the limits and what Pupitre does not protect
Part 8: Delivery08-delivery.mdThe build, the tests, the CI, the dependencies and the release

The configuration reference is part of section 6. The command pupitre print-reference --format markdown generates it from the table of keys in the code.

Key words

The key words MUST, MUST NOT, SHOULD and MAY are as RFC 2119 and RFC 8174 define them, when they are in capital letters.

Where to start

  • To run Pupitre, read the first guide and Operations.
  • To write a configuration file, read Configuration and part 6.
  • To understand the values and the runs, read Architecture, parts 2 and 4.
  • To set the access, read Access and part 3.
  • To review the security, read the security model and part 7.
